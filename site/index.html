01 / What's inside

Six things that earn their place

Everything here reads its state from the service, the package manager or the device. If something fails, the screen says so with the real error.

01headline

Authorisations you can trust

The list comes from the service and is cross-checked against Android's own package manager. When the two disagree you get both numbers and a diagnosis — never a silent zero.

02tools

Command center

Run shell commands through the service with its real privilege level. Exit codes, stderr and duration are shown exactly as they came back, with presets for the usual checks.

Package manager

Search third-party apps and disable, enable, clear or uninstall them through the service. Destructive actions confirm first and report what actually happened.

Device and One UI build, service state and privilege, wireless debugging, authorisation counts, storage and memory — copyable or exportable as text.

03 / The fix

The zero that wasn't zero

0 apps shown by 13.6.0
23 listed by this build
24 hold the permission

On Android 17 and One UI 9.0, Shizuku 13.6.0 reported “Authorized 0 applications” while every authorised app kept working. Android 17 changed the signature of the hidden getInstalledPackages call the service uses, so the package list came back empty. Authorisation was never broken — the reporting was.

This build carries the upstream fix and adds an independent cross-check straight from the package manager. The 24th app is the official manager itself, which always holds the permission it owns.

04 / Install

Sideload, start, verify

This is a self-signed build, so Android will ask you to allow installing unknown apps once. First time with ADB? The full Windows guide covers downloading the tools, enabling USB debugging and reading adb devices.

Install the APK

Download ShizukuReimagined.apk and install it. It coexists with the official Shizuku — nothing is replaced.

.\adb install -r ShizukuReimagined.apk

Start the service

Open the app once from the phone, then run its start script from the computer. No placeholders to fill in:

.\adb shell sh /sdcard/Android/data/net.xiondigital.shizuku/start.sh

Wireless debugging or root still work from inside the app if you prefer.

Check both are alive

The dashboard should say Service running and show the real uid and port.

.\adb shell ps -A | grep shizuku_server
# shizuku_server         (official)
# xion_shizuku_server    (this build)

05 / Coexistence

Two services, no collisions

Different package, process, config file and signing key. The native starter takes --server-name=, so starting this one cannot terminate the other.
