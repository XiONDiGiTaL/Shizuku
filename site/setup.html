Guide / Windows · macOS · Linux

Install from a computer

Two commands, no placeholders, no line continuations (PowerShell does not accept the \ continuation that cmd uses, which is why the old command failed for so many people). Roughly six minutes, once.

Get the Android platform-tools

adb ships in Google's platform-tools, not in Windows. Download it here (SDK Platform-Tools for Windows), then unzip it to C:\platform-tools so that C:\platform-tools\adb.exe exists. Do not run the installer from inside the zip.

macOS / Linux 
curl -O https://dl.google.com/android/repository/platform-tools-latest-darwin.zip
unzip platform-tools-latest-darwin.zip      # linux: -latest-linux.zip
cd platform-tools

Turn on USB debugging on the phone

Settings → About phone → Software information → tap Build number seven times. Go back one screen → Developer options → turn on USB debugging. On Samsung it lives at Settings → Developer options; on other phones it may be under System.

Plug in and authorise the computer

Use a data cable, not a charge-only one. When the phone asks, choose File transfer (some phones say Android Auto or Use USB for). Then accept Allow USB debugging?, tick Always allow from this computer.

Open a terminal in that folder and check the connection

In Explorer, open C:\platform-tools, then Shift + right-click the empty space → Open PowerShell window here. In cmd, cd /d C:\platform-tools. PowerShell needs the .\ prefix to run a program from the current folder; cmd does not.

PowerShell 
cd C:\platform-tools
.\adb devices
cmd 
cd /d C:\platform-tools
adb devices

You want your phone's serial followed by device: 

List of devices attached
R5CW71H8GEZ     device

Install Shizuku Reimagined

Download ShizukuReimagined.apk and move it into C:\platform-tools, next to adb.exe. The filename never changes between releases, so this command stays valid forever.

PowerShell 
.\adb install -r ShizukuReimagined.apk
cmd 
adb install -r ShizukuReimagined.apk

Expect Performing Streamed Install then Success.

Open the app once on the phone

Launch Shizuku Reimagined and let it draw the dashboard. This is what writes the start script the next command runs, the same idea as the official Shizuku's start.sh. Its path is also listed in Diagnostics → Application → ADB start script.

Start the service

One line, identical in PowerShell, cmd, Windows Terminal, macOS and Linux:

PowerShell / cmd 
.\adb shell sh /sdcard/Android/data/net.xiondigital.shizuku/start.sh
cmd, without the prefix 
adb shell sh /sdcard/Android/data/net.xiondigital.shizuku/start.sh
macOS / Linux 
./adb shell sh /sdcard/Android/data/net.xiondigital.shizuku/start.sh

The script prints the starter log and then stays in the foreground. That is the service running. 

info: starter begin
info: shizuku_starter exit with 0

The dashboard should now read Service running, ADB · API 13, uid 2000, port 5555.

Unplug

The service keeps running after the cable is removed (and after the adb command is closed), until the phone reboots, the app's Stop is pressed, or Android kills it for memory. Re-run the same command after a reboot.

When it does not work

What the error actually means

MessageCauseFix
'adb' is not recognized… You are not in the platform-tools folder, or used adb in PowerShell. cd C:\platform-tools, then .\adb devices.
Empty List of devices attached Charge-only cable or port, USB debugging off, or a missing driver. Try another cable (ideally the one that came with the phone) and a rear USB port, then .\adb kill-server and .\adb devices again.
Serial followed by unauthorized The phone's prompt was dismissed or denied. Unlock the phone, pull the cable, replug, and tap Allow with Always allow ticked. If no prompt appears: Developer options → Revoke USB debugging authorisations, replug.
Serial followed by offline Stale adb connection after a replug or sleep. .\adb kill-server, replug, .\adb devices.
sh: …/start.sh: No such file or directory The app has not been opened since install or update, so the script was never written, or external storage is unavailable. Open the app once and retry. Diagnostics → ADB start script shows the real path; if it says unavailable, the phone has no usable external storage.
Permission denied on the script Rare: the file lost its execute bit after a restore. .\adb shell chmod 755 /sdcard/Android/data/net.xiondigital.shizuku/start.sh
Service runs, but an app says it has no permission Authorisations belong to a package. Apps authorised for the official Shizuku are not authorised for this build. Open Authorizations in the app and grant access there; both builds can be authorised at once.

What the script contains: three lines, and the two paths change on every app update, which is why it is rewritten each time the app starts: 

#!/system/bin/sh
# Shizuku Reimagined: starts the service from a computer.
exec "/data/app/…/lib/arm64/libshizuku.so" --server-name=xion_shizuku_server --apk="/data/app/…/base.apk"

Prefer no cable? Wireless debugging and root both start the service from inside the app. This build never touches the official Shizuku's installation or its authorisations.
